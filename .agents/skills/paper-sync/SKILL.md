# Paper sync

Use the existing `paper/metadata.yaml` chapter order and `research/` registries. If absent, report missing private files; never replace an existing manuscript with a new one or reconstruct unpublished text from guesses.

For specialized scientific procedures, follow the scientific skill selection section of [AGENTS.md](../../../AGENTS.md): choose a relevant available module and read only needed supporting references. Preserve this project's evidence checks and manuscript workflow.

1. Finish the main project task and appropriate checks. Inspect actual changed files, relevant source code, source/result manifests and existing manuscript claims. Classify the contribution as method, design, observation, interpretation, limitation, reproducibility, or none. With no substantive contribution, leave prose unchanged and record only necessary state.
2. Register real evidence in `research/evidence.yaml`, including relative source paths and hashes, configuration, date, code identity (committed or explicitly uncommitted), environment, commands, verification scope and limitations. Use `planned`, `draft`, `verified`, `superseded`. Hash agreement and successful execution are not biological validation. If evidence changed, re-run appropriate analysis or downgrade it and every dependent confirmed claim; never merely refresh its checksum.
3. Update `research/claims.yaml` and numeric assertions against structured tables/JSON. Distinguish observation from interpretation, hypothesis and limitation. Existing frozen snapshots remain untouched. Do not infer FDR control for filtered candidates, absolute cell fractions, independent animals or age interactions from the current exploratory analyses.
4. Edit only relevant English chapters. Preserve correct material, negative results, denominators and publication status of references. Use claim markers `<!-- claim: C-ID -->` before supporting prose. Every important result statement must link to an evidence-backed claim, and key reported values must have numeric assertions. Keep English titles, captions, variables and terminology consistent. Use only verified BibTeX entries in confirmed literature claims; unresolved sources belong in the research backlog.
5. Update research progress, decisions, terminology and manuscript/submission todo items when needed. Preserve unresolved authorship, ethics/licenses, conflicts, literature coverage and target-specific AI disclosure as pending. No invented novelty or author roles. Read `docs/PAPER_WORKFLOW.md` for schemas and commands.
6. Run `bash envs/paper_python.sh scripts/check_paper.py`. Fix structural/evidence errors, record remaining warnings honestly, and do a semantic review after substantial prose changes: compare methods to implementation, configurations to runs, claims to results and abstract/conclusion to limitations. Record reviewed hashes and findings in `research/reviews/`; Codex review does not replace human scientific review.
7. Run `bash envs/paper_python.sh scripts/check_sync_readiness.py`. Prepare a meaningful English commit suggestion and identify the authorized release scope. The existing public code remote is not permission to publish ignored `paper/` or `research/`. Do not commit, push, upload or submit a manuscript without applicable user authorization. Weekly scheduling is a separate read-only automation.
8. Export through `bash scripts/export_paper.sh` only on request or an agreed milestone; daily edits remain Markdown. Do not use Word as another prose source. Review the rendered Word output and report format limitations before delivery. A school/journal template can replace the generic reference later; never guess its requirements.

Briefly report project results, affected paper chapters or no manuscript contribution, evidence status, machine/semantic review outcomes, Git readiness and next unresolved work. Do not claim the skill will run unattended or that its presence guarantees future model compliance; repository instructions provide the trigger and scripts provide observable checks.
